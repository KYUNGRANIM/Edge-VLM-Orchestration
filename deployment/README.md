# Deployment

The system that ran the final evaluation: the code on each device, the trained routers, and the records of the live run
on the 600 held-out images (November 2026).

| Path | Contents |
|---|---|
| `m5_firmware/` | Firmware of the three M5 agents, built with `platformio.ini`. `router_policy.cpp` is the Stage 1 router, generated by `export_device_router.py`. |
| `servers/` | The Pi_A, Pi_B, and Jetson servers. `stage2_policy.py` is the Stage 2 router, generated by `export_device_router.py`. |
| `routers/` | The trained routers (joblib files and readable tree text). |
| `live_run/` | Records of the live run (below). |
| `live_run_rescored/` | The live run's responses scored a second time by GPT-4o, to measure scoring repeatability. |
| `export_device_router.py` | Turns the routers into device code and checks the code against the routers and the live run. |
| `build_judge_input.py` | Builds the GPT-4o judge input from a run's responses. |

## `live_run/`

Final records, at the top level:

- `online_routing_final.jsonl`: one record per image with the responses of every tier the image reached, the routing
  decisions, and the timing.
- `judge_input.jsonl`, `00_judge.jsonl`, `01_quality.jsonl`: the judge input, the GPT-4o scores, and the quality
  components.
- `retry_ids.txt` … `retry5_ids.txt`: images re-run after failed M5 attempts, in five passes of 194, 112, 71, 11, and
  1 images.
- `jetson_resend_log.jsonl`: the Jetson answers of 91 images whose Jetson call timed out during the run and was re-sent
  afterwards with the same model and settings.

`judge_parts/` holds the judge input and output in the four parts in which they were scored.

`device_logs/` holds the raw logs of each device: the M5 SD-card logs of the main pass and of each retry pass
(`m5a_sd`, `m5a_sd_retry194`, …), the Pi_A logs with snapshots before and after the retry passes, the Pi_B and
Jetson logs, and the watchdog events. Table I's auxiliary-device energy and several checks read these logs.
